# 故事控制室

这是只给作者使用的本地后台，不会注入玩家页面，也不会在游戏前端显示任何图谱或编辑控件。

## 启动

在 `game` 目录运行：

```powershell
python story_server.py
```

然后打开：

`http://127.0.0.1:8767/story-control.html`

停止服务按 `Ctrl+C`。服务默认只监听本机地址；不要把它改成公网监听地址。

## 怎么看故事走向

- **故事图谱**：每张卡是一个节点，实线表示 `>_引用名` 或其他直接跳转，虚线表示“写入状态 → 读取状态”的可能牵动。
- **聚焦关联**：先选一张卡，再点“聚焦关联”，只保留它向后最多三层的关系和直接来源，适合检查一条线是否跑偏。
- **选中卡的状态关联**：默认关闭大规模状态连线；打开后只显示当前选中卡及其局部范围，避免 194 张卡的全量状态关系遮住主线。
- **颜色和形状**：金色是剧情连接，绿色是资源变化，灰绿是状态 / 伏笔，珊瑚色是结局；虚线边框代表相对基线有改动。

## 怎么看改了哪里

- **版本改动**以 `cards-independent.csv` 为项目基线，逐卡列出新增、删除和字段级变化。
- 详情面板会同时显示旧值和新值，并把“实际跳转目标变化”单独列出来。
- “以当前版为基线”只写入浏览器的 `localStorage`，不会修改项目文件；适合在一个阶段完成后重新开始计数。
- “导入对比基线”支持 CSV 或审阅 JSON，基线也只保存在当前浏览器。

## 怎么判断卡片有没有意义

机器体检只判断结构，不替作者决定文学价值：

- **错误**：断裂跳转、没有入口的续写卡等，优先修复。
- **警告**：没有写入来源的状态、可疑的行偏移跳转等，需要人工确认。
- **提示**：两侧机制结果相同、状态暂未回收，可能是氛围卡，也可能是无效卡。

在卡片详情里可以人工标记“关键剧情 / 节奏卡 / 待重写 / 无效 / 待删除”，并写备注。标记保存在浏览器；可从“更多”导出审阅 JSON。

## 编辑与保存

1. 在左侧索引或图谱中选卡，点击“编辑卡片”。
2. 修改只先进入工作区，顶部“尚未写回”会显示未保存卡数。
3. 点击“写回 cards.csv”后，服务端会先备份到 `.story-backups/`，再运行 `build.py` 校验并重新生成 `玩.html`。
4. 校验失败时会自动恢复 `cards.csv`，不会留下半成品牌库。

服务端还会检查文件版本；如果另一个程序先改过 `cards.csv`，保存会被拒绝，重新载入后再操作即可。

## 状态语法提醒

- `>_name`：按引用名跳转。
- `>name`：兼容旧格式的引用名跳转。
- `flag`：写入布尔状态；`!flag` 清除；`flag+` 增加计数器。
- 条件用 `and` 连接，例如 `cash<18 and !risk_cash_run`。

状态连线表达的是**可能的叙事牵动**，不等于每一局都会实际发生；最终是否成立还取决于玩家选择、资源数值、回合和冷却。
