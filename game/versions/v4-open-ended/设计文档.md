# 《任职》设计文档

一款商业经营题材的左右划卡游戏。玩家每次只回答一个具体问题，同时维持现金流、团队、
市场、资本四方关系。任何一项触底或爆表，CEO 都会下台；只要资源没有触发结局，就可以
一直玩下去，最后比较谁的在任时间更久。

当前默认卡组是 V4“开放任期”版本：日常卡随机出现，市场和团队各有一组短篇事件，
后果在同一局内回访。点击“再来一局”会清空资源、事件和计数器，从初始状态重新挑战。
V3 反馈优先版本保存在 `versions/v3-feedback-first/`，早期独立剧情保存在 `cards-independent.csv`，
V2 的强制四幕线保存在 `versions/v2-merged-linear/`，这些版本互不混写。

---

## 一、四条资源

四条资源既是生存值，也是四方势力。界面不显示具体数字，只用图标、黄点高度、动画和
选择预告表达趋势。

| 槽 | 代表谁 | 归零 | 爆表 |
|---|---|---|---|
| **现金流** | 财务 | 发不出工资 | 钱躺着不投，错过窗口 |
| **团队** | 员工 | 人去楼空 | 人浮于事，成本压垮利润 |
| **市场** | 客户 | 没人买 | 订单接不过来，交付崩盘 |
| **资本** | 董事会 / 投资人 | 被罢免 | 被资本架空，推着上市套现 |

资源内部仍为 0–100。普通变化以 5–15 为主，让玩家看趋势就能判断，不要求心算。

每项资源在一任内各有一次临界补救。补救能把玩家从红线拉回来，但会制造债务、让权、
客户控制或伙伴关系等后果。它是一次带代价的翻盘，不是免死。

## 二、下台方式

### 资源结局

| 触发 | 结局 | 结束说明 |
|---|---|---|
| 现金流=0 | 破产清算 | 工资发不出去，公司进入清算 |
| 现金流=100 | 守财奴 | 钱没有花出去，窗口期错过 |
| 团队=0 | 人去楼空 | 核心成员离职，团队解散 |
| 团队=100 | 大锅饭 | 人力成本吞掉利润 |
| 市场=0 | 无人问津 | 产品还在，但没人需要 |
| 市场=100 | 爆单崩盘 | 订单越多，赔得越多 |
| 资本=0 | 一致行动 | 董事会完成换人 |
| 资本=100 | 功成身退 | 公司进入新阶段，你体面离场 |

没有固定的第 N 次复盘，也没有强制的任期上限。资源结局或明确的卡牌剧情结局出现时，
这一局才会结束。结局页显示本局在任时长，重新开始后不携带任何旧状态。

## 三、反馈优先短篇

V4 不要求玩家记住一条长任务线。每一局只需要处理眼前的一件事；选择的代价会在几张卡
之后回来，卡面会重新说清“你之前做了什么”。重新开始后，上一局的合同、关系和计数器全部清空。

| 层次 | 作用 | 玩家看到的形式 |
|---|---|---|
| **日常卡** | 现金、团队、市场、资本的即时权衡 | 一句话问题 + 两个动作选项 |
| **临界补救** | 资源接近红线时给一次带代价的翻盘 | 先救急，随后留下债务或关系变化 |
| **任内短篇** | 市场或团队的一次决定，数回合后回访 | “当时你选择了……”的具体追问 |
| **后果回访** | 让本局的选择留下痕迹 | 几张卡后直接面对合同、欠款或旧同事 |
| **开放任期** | 没有预设的回合终点 | 资源安全，就可以继续经营 |

短篇事件使用 `xxx_run` 记录当前一局的选择，使用 `xxx_keep` 记录几张卡后要回来的
合同、债务、关系和证据。`nb_xxx+` 只用于本局累计次数，不再依赖固定幕数。

| 写法 | 生命周期 | 用途 |
|---|---|---|
| `xxx_run` | 仅当前一局 | 记录短篇走到哪一步、是否已经回访 |
| `xxx_keep` | 仅当前一局 | 记录合同、关系、证据与历史污点 |
| `nb_xxx+` | 仅当前一局 | 某类事件发生次数等累积状态 |

## 四、单任节奏

目标是每局 4–8 分钟，具体长度由玩家的经营水平和风险偏好决定：

| 决策位置 | 叙事功能 |
|---|---|
| 1 | 开场或接任，立刻说清眼前问题 |
| 5 左右 | 一次短篇或临界补救，立刻看见代价 |
| 9 左右 | 早期选择第一次回来索取代价 |
| 11–14 | 伙伴、客户或资本立场发生反转 |
| 15 以后 | 长任期事件逐步出现，资源安全就继续经营 |
| 结局时 | 某条资源触底/爆表，或卡牌明确触发结局 |

顶部右侧直接显示“在任 X 个月 / X 年”，让玩家知道自己的成绩；左侧保留当前任次，资源槽
仍不显示具体数值，只用图标、黄点高度、动画和选择预告表达趋势。

模拟基准：随机选择会较早触发资源结局；会根据资源预告回避红线的玩家可以持续数十张卡，
直到某条资源或剧情真正失控。紧张感来自还能不能补救，而不是倒计时。

## 五、卡牌表结构

一行一张卡，共 22 列：

```text
thematic  card  id  bearer  conditions  lockturn  weight  question
override_yes  answer_yes  yes_cash  yes_team  yes_market  yes_capital  yes_custom
override_no   answer_no   no_cash   no_team   no_market   no_capital   no_custom
```

有 `weight` 的卡可以随机进入牌堆；权重留空的续写卡只能由 `>` 跳入。常用跳转为：

| 写法 | 意思 |
|---|---|
| `>` | 下一张卡 |
| `>>>` | 向后跳三张 |
| `>_card_name` | 跳到指定卡名 |

条件只使用 `and`、`!`、`<`、`>`、`=`、`<=`、`>=`。高于 1000 的权重用于剧情节拍，
普通日常卡维持在 8–16，资源结局为 1000000。

当前默认卡组 136 张：79 张日常卡、8 张临界补救、两组各 5 条短篇分支、11 张本局后果回访
和 8 种资源结局。数值变化中位数为 8，90 分位为 15；选择结果不再在卡片下方重复列资源，
而由资源槽的方向动画表达。

## 六、构建与检查

```powershell
python -X utf8 build.py
python -X utf8 sim.py --runs 500
python -X utf8 sim.py --runs 500 --smart
```

构建器同时检查默认版和独立版的 22 列结构，并验证重复 id、重复 card、跳转目标、孤立续写
卡和未被写入的条件状态。默认版通过后才会生成 `玩.html`。
