# 《任职》设计文档

一款商业经营题材的左右划卡游戏。玩家每次只回答一个具体问题，同时维持现金流、团队、
市场、资本四方关系。任何一项触底或爆表，CEO 都会下台；公司不会重置，前任签过的合同、
得罪的人和撒过的谎会继续找下一任。

当前默认卡组是 V3“反馈优先”版本：日常卡随机出现，市场和团队各有一组短篇事件，
少量后果卡会在下一任明确回访。早期的四条独立剧情已完整保存在 `cards-independent.csv`，
V2 的强制四幕线保存在 `versions/v2-merged-linear/`，两者都不与默认版混写。

---

## 一、四条资源

四条资源既是生存值，也是四方势力。界面不显示具体数字，只用图标、黄点高度、动画和
选择预告表达趋势。

| 槽 | 代表谁 | 归零 | 爆表 |
|---|---|---|---|
| **现金流** | 财务 | 发不出工资 | 钱躺着不投，错过窗口 |
| **团队** | 员工 | 人去楼空 | 人浮于事，成本压垮利润 |
| **市场** | 客户 | 没人买 | 订单接不过来，交付崩盘 |
| **资本** | 董事会 / 投资人 | 被罢免 | 被资本架空，推着上市套现 |

资源内部仍为 0–100。普通变化以 5–15 为主，让玩家看趋势就能判断，不要求心算。

每项资源在一任内各有一次临界补救。补救能把玩家从红线拉回来，但会制造债务、让权、
客户控制或伙伴关系等后果。它是一次带代价的翻盘，不是免死。

## 二、下台方式

### 资源结局

| 触发 | 结局 | 下一任的处境 |
|---|---|---|
| 现金流=0 | 破产清算 | 现金 15，债务仍在 |
| 现金流=100 | 守财奴 | 现金 85，市场窗口已经缩小 |
| 团队=0 | 人去楼空 | 团队 15，招聘口碑受损 |
| 团队=100 | 大锅饭 | 团队 85，现金承压 |
| 市场=0 | 无人问津 | 市场 15，重新寻找客户 |
| 市场=100 | 爆单崩盘 | 市场 80，团队被交付拖垮 |
| 资本=0 | 一致行动 | 资本 20，董事会严密监督 |
| 资本=100 | 功成身退 | 资本 85，公司进入上市规则 |

### 剧情结局

任期不会只等玩家靠资源死掉。第 18 次决策进入董事会复盘，依据这一任留下的选择触发：

| 结局 | 含义 |
|---|---|
| 融资换帅 | 钱或交易保住公司，资本拿走位置 |
| 联创反杀 | 伙伴带走人、产品或董事会支持 |
| 替罪离场 | 公司把系统性问题写成个人判断 |
| 止损离场 | 玩家做对了程序，仍因损失被换掉 |
| 低价卖身 | 旧债迫使公司接受不对等收购 |
| 任满交棒 | 这一任处理得体，由玩家主动离开 |

下台不是失败弹窗，而是因果链的一部分。上一任的结局决定下一任的初始资源和开场台词。

## 三、反馈优先短篇

V3 不要求玩家记住一条长任务线。每一任只需要处理眼前的一件事；选择的代价会在几张卡
之后回来，卡面会重新说清“上次发生了什么”，下一任则用一张后果卡再提醒一次。

| 层次 | 作用 | 玩家看到的形式 |
|---|---|---|
| **日常卡** | 现金、团队、市场、资本的即时权衡 | 一句话问题 + 两个动作选项 |
| **临界补救** | 资源接近红线时给一次带代价的翻盘 | 先救急，随后留下债务或关系变化 |
| **任内短篇** | 市场或团队的一次决定，数回合后回访 | “当时你选择了……”的具体追问 |
| **后果回访** | 让前任的选择真的留下痕迹 | 下一任直接面对合同、欠款或旧同事 |
| **董事会复盘** | 最迟第 18 次决策结束这一任 | 资源足够也可能被换，或体面交棒 |

短篇事件使用 `xxx_run` 记录当前任期的选择，使用 `xxx_keep` 记录需要跨任回来的
合同、债务、关系和证据。`nb_xxx+` 只用于累计次数，不再依赖 `nb_story` 推进固定幕数。

| 写法 | 生命周期 | 用途 |
|---|---|---|
| `xxx_run` | 仅当前任期 | 记录短篇走到哪一步、是否已经回访 |
| `xxx_keep` | 跨任继承 | 记录合同、关系、证据与历史污点 |
| `nb_xxx+` | 跨任计数 | 某类事件发生次数等累积状态 |

## 四、单任节奏

目标是 4–6 分钟一任，而不是等资源随机耗尽：

| 决策位置 | 叙事功能 |
|---|---|
| 1 | 开场或接任，立刻说清眼前问题 |
| 5 左右 | 一次短篇或临界补救，立刻看见代价 |
| 9 左右 | 早期选择第一次回来索取代价 |
| 11–14 | 伙伴、客户或资本立场发生反转 |
| 15–16 | 明示董事会复盘临近，给玩家收尾感 |
| 18 | 剧情结局；临界救援插入时最迟约第 20 张 |

顶部文字直接显示这一任还剩多少次决定（如“还剩 17 次”），让玩家知道节奏，但不泄露资源数值。

模拟基准：随机选择时，大多数任期落在 18–20 张；会根据资源预告回避红线的玩家，几乎
都能走到计划终局。紧张感来自“还能不能补救”和“代价会落到谁头上”，而不是无提示暴毙。

## 五、卡牌表结构

一行一张卡，共 22 列：

```text
thematic  card  id  bearer  conditions  lockturn  weight  question
override_yes  answer_yes  yes_cash  yes_team  yes_market  yes_capital  yes_custom
override_no   answer_no   no_cash   no_team   no_market   no_capital   no_custom
```

有 `weight` 的卡可以随机进入牌堆；权重留空的续写卡只能由 `>` 跳入。常用跳转为：

| 写法 | 意思 |
|---|---|
| `>` | 下一张卡 |
| `>>>` | 向后跳三张 |
| `>_card_name` | 跳到指定卡名 |

条件只使用 `and`、`!`、`<`、`>`、`=`、`<=`、`>=`。高于 1000 的权重用于剧情节拍，
普通日常卡维持在 8–16，资源结局为 1000000。

当前默认卡组 143 张：80 张日常卡、8 张临界补救、两组各 5 条短篇分支、11 张后果回访
和 14 种结局。数值变化中位数为 8，90 分位为 15；选择结果不再在卡片下方重复列资源，
而由资源槽的方向动画表达。

## 六、构建与检查

```powershell
python -X utf8 build.py
python -X utf8 sim.py --runs 500 --tenures 8
python -X utf8 sim.py --runs 500 --tenures 8 --smart
```

构建器同时检查默认版和独立版的 22 列结构，并验证重复 id、重复 card、跳转目标、孤立续写
卡和未被写入的条件状态。默认版通过后才会生成 `玩.html`。
